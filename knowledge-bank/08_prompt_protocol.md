# 外层程序与 CORE 的提示协议

CORE 不负责猜标签含义。外层程序必须先完成：LabelMe 解析、标签映射、参考选择、ROI mask 构造、提示词组装和审核意见翻译。

## 初次生成提示结构

1. 任务：在输入工业设备图上执行局部反事实编辑。
2. 标签：列出代码、中文名、异常族和具体动作。
3. 位置：说明白色 ROI mask 是当前 shape 的允许编辑和定位区域；若输入像素确实烧录了框线/文字，则只在该区域内无痕去除。
4. 正向规则：从 `labels.json` 插入该标签的物理结构和视觉规律。
5. 负向规则：禁止改变的结构、背景和成像属性。
6. 输出约束：同尺寸、无标注、灰度一致、只返回编辑后图像。
7. 参考声明：参考图只提供异常规律，禁止复制参考设备身份与背景。

## 多标签

多 shape 同图时，默认把每个 shape 展开成独立任务。正常图 JSON 中为当前类别标一个框、再随机附加其他异常类别框时，三个框必须分别处理，不得一次生成三个异常。`joint` 只作为显式兼容选项。

## 再生成

程序从审核表读取结构化原因码和补充说明，将 `feedback_rules.json` 中的修正规则附加到原提示。新尝试必须继承原始源图、LabelMe、参考索引和所有历史审核，不允许基于上一版候选反复累积编辑。

每次再生成都从干净源图开始，版本号递增；旧版本保留在本次运行的中间产物中供追溯。
